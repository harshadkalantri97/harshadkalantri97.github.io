Generic JSON Parser

Designed & built
Problem
Multi-level JSON arriving from varied network sources did not map cleanly onto database-ready records, and per-source parsers multiplied maintenance.
Approach
Built one streaming parser that reads JSON token by token straight into a compact row buffer, with no intermediate object tree. Parent fields are reused across array rows instead of copied, a DBID level setting maps each branch of the hierarchy into its own data block, and JSON Lines input is detected automatically.
Result
45% performance gain over the existing JSON parsers it replaced.
JavaJSONData ModellingPerformance

04 / Playground

Try the JSON parser

A browser port of the flattening rules in my Generic JSON Parser. The production version is Java and streams tokens with jsoniter. This one follows the same rules, token by token, and runs only in your browser. Nothing is uploaded.

Samples
input
Level 0: stream rowsA row leaves the moment each array element is read, carrying every field seen before the array. Nested arrays become indexed columns such as cells.counters.0.name, which is why header fields come first in real PM files.
Level 1 and up: data blocksEach branch of the tree, down to the chosen depth, becomes its own data block. Blocks are buffered, their headers merged, and short rows padded before output.
JSON LinesIf the first line is a complete JSON value, every line is read as its own document. It is the same check the parser makes before choosing how to read a file.
